# TanStack NPM 공급망 공격 정리

## 공급망 공격(Supply Chain Attack)이란?

공급망 공격은 사용자를 직접 공격하는 것이 아니라,
사용자가 신뢰하는 라이브러리·패키지·업데이트 서버 등을 악용해 침투하는 공격 방식이다.

예를 들어 개발자가 정상적인 NPM 패키지를 설치했는데,
그 패키지에 악성 코드가 포함되어 있다면 개발 환경 전체가 위험해질 수 있다.

---

# TanStack NPM 공급망 공격이란?

일부 TanStack 관련 NPM 패키지 배포 과정이 공격받아
악성 코드가 포함된 패키지가 배포된 사건이다.

> TanStack : React에서 API 요청과 상태 관리를 쉽게 해주는 라이브러리(서버 데이터 관리, 테이블 UI, 라우팅, 가상 스크롤, 상태 관리)


개발자가 해당 패키지를 설치하면:

* 환경 변수 탈취
* GitHub Token 유출
* AWS/API Key 탈취
* CI/CD 정보 수집

등의 위험이 발생할 수 있었다.

---

# 왜 일어났나?

주요 원인은 다음과 같다.

## 1. 배포 권한 탈취

공격자가 유지보수 계정 또는 배포 토큰을 탈취했다.

## 2. NPM 생태계 특성

오픈소스 패키지는 수많은 프로젝트가 의존하고 있어
한 번 오염되면 매우 빠르게 확산된다.

## 3. 자동 업데이트 문제

많은 프로젝트가 `latest` 또는 `^버전`을 사용해
악성 버전이 자동 설치되었다.

---

# 어떻게 해결되었나?

## 1. 악성 패키지 제거

문제가 된 버전은 NPM에서 제거되거나 차단되었다.

## 2. 안전한 버전 재배포

정상 코드만 포함된 새 버전이 다시 배포되었다.

## 3. 토큰 및 인증 정보 교체

영향 가능성이 있는 사용자들은:

* GitHub Token 교체
* NPM Token 재발급
* API Key 변경
* CI/CD Secret 초기화

등을 진행했다.

## 4. 보안 강화

이후 다음 보안 조치가 강화되었다.

* MFA(다중 인증)
* 최소 권한 원칙
* 의존성 감사
* 패키지 서명 및 provenance 검증

---

# 핵심 교훈

* 신뢰하는 오픈소스도 공격 대상이 될 수 있다.
* 자동 업데이트는 편리하지만 위험할 수 있다.
* 개발 환경의 Secret 관리가 매우 중요하다.
* 공급망 보안과 의존성 관리가 필수다.
