# 🔐 기존 암호학 vs ⚛️ 양자컴퓨터

## 1. 개요

현재 우리가 사용하는 대부분의 암호학은 **수학적 난이도(계산 복잡도)**에 기반한다.

대표적으로는 다음과 같다.

- 큰 수의 소인수분해 문제
- 이산 로그 문제
- 타원곡선 기반 문제

이러한 문제들은 **클래식 컴퓨터에서는 매우 느리게 풀리는 문제**이기 때문에 안전하다고 여겨진다.

---

## 2. 기존 암호학의 핵심 원리

### 기본 구조

- 공개키(Public Key) + 개인키(Private Key)
- 특정 수학적 문제 기반
- 역연산이 매우 어려움

---

### 대표 알고리즘

| 알고리즘 | 기반 문제 |
|----------|----------|
| RSA | 소인수분해 |
| DSA | 이산 로그 |
| ECC | 타원곡선 이산 로그 |

핵심:
> 계산은 쉽지만 되돌리는 것은 매우 어렵다

---

## 3. 양자컴퓨터의 등장

| 구분 | 기존 컴퓨터 | 양자컴퓨터 |
|------|------------|------------|
| 연산 | 비트 | 큐비트 |
| 특징 | 순차 처리 | 중첩 + 병렬성 |
| 성능 | 제한적 | 특정 문제에서 압도적 |

---

## 4. 기존 암호학이 위험해지는 이유

주요 알고리즘:

- 쇼어 알고리즘
  - 소인수분해 / 이산로그를 빠르게 해결
  - RSA, ECC 붕괴

- 그로버 알고리즘
  - brute-force 속도 향상
  - 대칭키 보안 강도 감소

---

## 5. 양자컴퓨터 시대의 변화

- 공개키 암호 → 대부분 취약
- 대칭키 → 키 길이 증가로 유지 가능
- 보안 기준 → 양자 공격 고려

---

# 6. HTTP / HTTPS는 안전할까?

## 6.1 HTTP

완전히 안전하지 않음

- 암호화 없음
- 데이터 노출
- MITM 공격 가능

결론:
> HTTP는 이미 위험함

---

## 6.2 HTTPS 구조

1. 공개키 암호 (RSA/ECC) → 키 교환
2. 대칭키 암호 (AES) → 데이터 암호화

---

## 6.3 양자컴퓨터 영향

- RSA / ECC → 붕괴
- 키 교환 과정 깨짐

결론:
> HTTPS도 안전하지 않게 됨

---

## 6.4 대응 방법 (핵심 이해)

양자컴퓨터로 인해 기존 공개키 암호가 깨지기 때문에  
**"키를 안전하게 교환하는 방식"을 바꾸는 것이 핵심이다**

---

### 1) 양자 내성 암호(PQC) 적용

기존 RSA/ECC 대신  
양자컴퓨터로도 풀기 어려운 알고리즘을 사용

예:
- Kyber → 키 교환
- Dilithium → 서명

👉 의미
> "양자컴퓨터가 있어도 계산적으로 못 깨게 설계"

---

### 2) 하이브리드 TLS (현실적인 과도기 전략)

기존 방식 + PQC를 **동시에 사용**

예시 흐름:

1. 기존 방식 (RSA/ECC)으로 키 교환
2. PQC 방식으로 추가 키 교환
3. 두 결과를 합쳐서 최종 키 생성

---

👉 왜 이렇게 하냐?

- PQC는 아직 완전히 검증되지 않음
- 기존 암호는 지금 당장 안전함

👉 그래서
> "둘 다 써서 하나라도 안전하면 OK" 전략

---

### 3) TLS 관점에서 보면

기존:


클라이언트 → 서버 : 공개키 요청
서버 → 클라이언트 : RSA 공개키 전달
→ 키 교환


변경:


클라이언트 → 서버 : PQC + 기존 방식 요청
서버 → 클라이언트 : 두 방식 모두 제공
→ 두 키를 결합해서 세션 키 생성
### 4) 핵심 요약

- 문제의 본질 = 키 교환이 깨짐
- 해결 방법 = 새로운 키 교환 알고리즘 도입
- 현실 방법 = 기존 + PQC 같이 사용

---

## 6.5 현실적 위협

Harvest Now, Decrypt Later

현재 데이터 저장 → 미래에 복호화

위험 데이터:
- 금융 정보
- 개인정보
- 기밀 데이터

---

# 7. 결론

- 기존 암호학 → 양자컴퓨터에 취약
- 공개키 암호 → 가장 큰 영향
- 대칭키 → 일부 유지 가능

---

# 8. 한줄 요약

양자컴퓨터는 암호를 빠르게 푸는 것이 아니라  
암호의 전제 자체를 무너뜨리는 기술이다
