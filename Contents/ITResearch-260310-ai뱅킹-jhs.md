# AI 뱅킹

## 1세대 AI 뱅킹 (현재)

특징

- 은행 앱 내부에 AI 챗봇이 존재
- 사용자가 챗봇과 대화 후 특정 기능을 실행
- 실제 금융 거래는 기존 앱 UI / 백엔드 로직이 수행

구조

사용자
->
은행 앱
->
AI 챗봇 (개발자가 특정 시점에 특정 API를 호출하도록 개발)
->
기존 금융 API
->
은행 시스템

예시

- 계좌 조회
- 간단한 이체
- 금융 FAQ
- 상품 추천

핵심

AI = 앱 기능을 보조하는 인터페이스 (화면단의 대체)

---

## 2세대 AI 뱅킹 (다가오는 단계)

특징

- AI가 금융 서비스를 직접 오케스트레이션
- 여러 금융 API를 조합하여 서비스 수행
- 챗봇이 아니라 AI 금융 비서 역할

구조

사용자
->
AI 금융 Agent (사용자와의 대화를 통해 직접 API를 호출)
->
AI Gateway (인증, 권한제한, 로그적재 등 AI의 서비스 접근 관리)
->
은행 API
->
은행 시스템

예시

"다음달 여행가려고 200만원 모아줘"

AI 수행

지출 분석
->
저축 가능 금액 계산
->
적금 상품 선택
->
자동 가입

핵심

AI = 금융 서비스 실행 주체

---

## 3세대 AI 뱅킹 (미래)

특징

- OS 수준 AI가 금융 서비스를 통합
- 사용자는 특정 은행 앱을 직접 사용하지 않음
- AI가 여러 금융기관을 비교 후 실행

구조

사용자
->
OS AI / Personal AI
->
Financial Gateway (은행/증권/보험/카드을 묶어 하나로 제공하는 금융서비스허브)
->
은행 / 증권 / 보험 API

예시

"내 돈 최적으로 관리해줘"

AI 수행

은행 A 예금
증권사 B ETF
보험사 C 상품
자동 조합

핵심

금융 서비스 = AI가 호출하는 API

# 개발자 관점 시사점

## 1. AI 친화적 API 설계

AI가 이해하기 쉬운 구조 필요 (semantic API)

특징
- 의미 기반 endpoint
- 명확한 파라미터
- 일관된 데이터 구조

예)

```
/v1/acnt/inq
/v1/trns/exec
/v1/dep/prd/open

ACNO
TR_AMT
CUST_ID 보단
```
```
POST /transfer
POST /create_savings_plan
GET /spending_analysis
POST /apply_loan

/accounts
/transfer
/deposit-products 가 더 semantic !
```

핵심

사람이 아니라 AI가 읽는 API 설계

## 2. AI Gateway 필요성

AI가 금융 API를 안전하게 호출하도록 중간 계층 필요

구조

AI Agent
->
AI Gateway
->
은행 API

Gateway 역할

- AI 인증
- 권한 관리
- 거래 제한
- 호출 로그
- 보안 정책
