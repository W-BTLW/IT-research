# LLM은 한국어를 어떻게 이해할까?

## 1. 개요

ChatGPT와 같은 LLM(Large Language Model)은 사용자가 입력한 한국어를 자연스럽게 이해하고 답변한다.

예를 들어 사용자가

```text
오늘 서울 날씨가 어때?
```

라고 질문하면 AI는 이것이 단순한 문자들의 조합이 아니라 **서울의 오늘 날씨를 묻는 질문**이라는 문맥을 파악한다.

그렇다면 컴퓨터는 어떻게 한국어를 이해할 수 있을까?

컴퓨터가 사람처럼 한글 자체의 의미를 직접 이해하는 것은 아니다.

LLM은 한국어 문장을 **작은 단위로 나누고 이를 숫자로 변환한 뒤, 학습된 언어의 패턴을 이용해 문장의 의미와 관계를 파악한다.**

전체적인 흐름은 다음과 같다.

```text
한국어 입력
   ↓
문장을 작은 단위(Token)로 분리
   ↓
Token을 숫자로 변환
   ↓
단어와 문장의 관계 분석
   ↓
문맥 파악
   ↓
답변 생성
```

---

# 2. 첫 번째 과정 - 문장을 Token으로 나눈다

LLM은 사용자가 입력한 문장을 그대로 처리하지 않는다.

먼저 문장을 **Token(토큰)**이라는 작은 단위로 나눈다.

Token은 AI가 언어를 처리하는 기본 단위라고 생각하면 된다.

예를 들어

```text
나는 오늘 회사에 출근했다.
```

라는 문장이 있다면 모델에 따라

```text
나는 / 오늘 / 회사 / 에 / 출근 / 했다 / .
```

또는

```text
나 / 는 / 오늘 / 회사 / 에 / 출근 / 했 / 다 / .
```

와 비슷하게 나누어질 수 있다.

즉,

> Token은 반드시 하나의 단어를 의미하는 것이 아니라 글자, 단어 또는 단어의 일부가 될 수 있다.

이렇게 문장을 Token 단위로 나누는 과정을 **Tokenization(토큰화)**이라고 한다.

---

# 3. 두 번째 과정 - Token을 숫자로 변환한다

컴퓨터는

```text
회사
출근
오늘
```

같은 한국어 자체를 직접 계산할 수 없다.

따라서 각각의 Token을 컴퓨터가 처리할 수 있는 숫자로 변환한다.

예를 들어 이해를 위해 단순하게 표현하면

```text
나는  → 1521
오늘  → 8210
회사  → 3921
출근  → 7214
했다  → 9210
```

와 같은 방식이다.

따라서

```text
나는 오늘 회사에 출근했다.
```

라는 문장은 내부적으로

```text
[1521, 8210, 3921, 7214, 9210]
```

와 같은 숫자 형태로 처리될 수 있다.

여기서 숫자 자체가 단어의 의미를 나타내는 것은 아니다.

예를 들어

```text
회사 = 3921
```

이라고 하더라도 숫자 `3921` 자체가 회사라는 의미를 가지고 있는 것은 아니다.

Token을 구분하기 위한 번호라고 이해하면 된다.

---

# 4. 세 번째 과정 - 숫자에 의미와 관계를 표현한다

Token을 숫자로 변환했다고 해서 AI가 바로 문장의 의미를 이해할 수 있는 것은 아니다.

LLM은 각각의 Token을 다시 **여러 숫자로 구성된 형태(Vector)**로 표현한다.

이를 **Embedding(임베딩)**이라고 한다.

중요한 것은 이 숫자의 실제 값이 아니라 **단어 사이의 관계를 숫자로 표현할 수 있다는 점**이다.

LLM은 대량의 한국어 문장을 학습하면서 다음과 같은 관계를 자연스럽게 학습한다.

```text
은행 ↔ 계좌 ↔ 예금 ↔ 대출 ↔ 금융

회사 ↔ 직원 ↔ 업무 ↔ 출근

학교 ↔ 학생 ↔ 수업 ↔ 선생님
```

예를 들어 학습 데이터에서

```text
은행에서 돈을 인출했다.
은행에서 대출을 받았다.
은행 계좌를 만들었다.
은행에 돈을 예금했다.
```

같은 문장을 많이 학습하면

```text
은행
돈
계좌
대출
예금
```

이라는 표현들이 서로 관련성이 높다는 패턴을 학습하게 된다.

즉, 사람이 직접 AI에게

```text
은행은 금융기관이다.
은행에서는 대출을 받을 수 있다.
은행에는 계좌가 있다.
```

라는 규칙을 하나씩 입력하는 것이 아니다.

**대량의 문장을 학습하면서 단어들이 어떤 상황에서 함께 사용되는지를 스스로 학습하는 것이다.**

---

# 5. 네 번째 과정 - 문맥을 이용해 의미를 판단한다

한국어에서는 같은 단어라도 문장에 따라 의미가 달라질 수 있다.

대표적인 예가 **은행**이다.

다음 두 문장을 비교해보자.

```text
① 은행에서 돈을 찾았다.

② 길에서 은행을 주웠다.
```

첫 번째 문장의 은행은 **금융기관**을 의미한다.

두 번째 문장의 은행은 **은행나무 열매**를 의미한다.

LLM이 단순히

```text
은행 = 금융기관
```

이라고만 기억하고 있다면 두 번째 문장을 제대로 해석할 수 없다.

그래서 LLM은 해당 단어 하나만 보는 것이 아니라 **앞뒤에 있는 다른 Token과의 관계를 함께 분석한다.**

```text
은행 + 돈 + 계좌 + 대출
        ↓
금융기관일 가능성이 높음
```

반대로

```text
은행 + 나무 + 열매 + 냄새
        ↓
은행나무와 관련된 의미일 가능성이 높음
```

이처럼 주변 단어와 문장 전체의 흐름을 이용하여 의미를 판단한다.

이것이 LLM이 자연스러운 한국어 문장을 이해하는 데 중요한 **Context(문맥)**의 개념이다.

---

# 6. 조사와 어순도 문맥으로 파악한다

한국어는 영어와 달리 조사가 많이 사용된다.

예를 들어

```text
철수가 영희에게 사과를 주었다.
```

라는 문장에서

```text
철수가 → 행동의 주체

영희에게 → 행동의 대상

사과를 → 전달한 대상

주었다 → 행동
```

라는 관계가 존재한다.

LLM은 수많은 한국어 문장을 학습하면서

```text
은 / 는
이 / 가
을 / 를
에게
에서
으로
```

등이 문장에서 어떤 역할을 하는지에 대한 패턴도 함께 학습한다.

따라서 단순히 단어의 뜻만 보는 것이 아니라

```text
누가
무엇을
누구에게
어떤 행동을 했는지
```

와 같은 문장 전체의 관계를 파악할 수 있다.

---

# 7. 오타가 있어도 어느 정도 이해하는 이유

LLM은 정확하게 작성된 문장만 처리할 수 있는 것은 아니다.

예를 들어

```text
오늘 서울 날씨 알려줘
```

대신

```text
오눌 서울 날씨 알랴줘
```

처럼 일부 오타가 있어도 질문의 의미를 파악하는 경우가 많다.

LLM이 단순한 사전 검색 방식으로 동작하는 것이 아니라 **전체 문장의 패턴과 문맥을 함께 분석하기 때문**이다.

```text
오눌 + 서울 + 날씨 + 알랴줘
              ↓
"오늘 서울 날씨를 알려달라는 질문이구나"
```

처럼 주변 정보와 학습된 언어 패턴을 이용해 의도를 추론할 수 있다.

다만 오타가 너무 많거나 문맥이 부족하면 잘못 해석할 수도 있다.

---

# 8. 전체 과정을 하나의 예시로 정리

사용자가 다음과 같이 입력했다고 가정해보자.

```text
은행에서 대출을 받고 싶어
```

LLM이 이를 처리하는 과정을 단순화하면 다음과 같다.

```text
[1] 한국어 입력

"은행에서 대출을 받고 싶어"

        ↓

[2] Tokenization

은행 / 에서 / 대출 / 을 / 받고 / 싶어

        ↓

[3] 숫자로 변환

각 Token을 컴퓨터가 계산할 수 있는 숫자로 변환

        ↓

[4] 단어 사이의 관계 분석

은행 ↔ 대출
대출 ↔ 받다
은행 ↔ 금융

        ↓

[5] 문맥 파악

"은행의 대출과 관련된 내용을 원하는 질문"

        ↓

[6] 학습된 언어 패턴을 이용하여
적절한 답변 생성

        ↓

[7] 한국어 답변 출력
```

---

# 9. 그렇다면 AI는 한국어를 정말 이해하는 것일까?

사람은 한국어를 읽을 때 자신의 경험과 지식을 이용해 의미를 이해한다.

반면 LLM은 기본적으로 방대한 텍스트를 학습하면서 얻은 **단어와 문장 사이의 패턴을 수학적으로 계산**한다.

따라서 AI가 사람과 완전히 동일한 방식으로 한국어를 이해한다고 보기는 어렵다.

하지만 수많은 한국어 문장을 학습하면서

```text
단어의 의미
문장의 구조
단어 사이의 관계
앞뒤 문맥
질문의 의도
```

등을 매우 정교하게 파악할 수 있게 되었고, 결과적으로 사람과 자연스럽게 대화할 수 있는 수준의 언어 처리 능력을 가지게 된 것이다.

---

# 10. 정리

LLM이 한국어를 처리하는 핵심 과정은 다음과 같다.

```text
한국어 문장 입력
        ↓
Token 단위로 분리
        ↓
Token을 숫자로 변환
        ↓
숫자를 의미를 표현하는 형태로 변환
        ↓
단어 사이의 관계 분석
        ↓
전체 문맥과 질문의 의도 파악
        ↓
적절한 한국어 답변 생성
```

즉,

> **LLM은 한국어 자체를 사람처럼 읽는 것이 아니라, 한국어를 Token과 숫자로 변환하고 대량의 한국어 데이터에서 학습한 단어·문장 간의 관계와 문맥을 이용하여 의미를 해석한다.**

이러한 과정 덕분에 LLM은 단순한 단어 검색을 넘어 문맥을 이해하고, 같은 단어의 서로 다른 의미를 구분하며, 자연스러운 한국어 질문에 적절한 답변을 생성할 수 있다.
