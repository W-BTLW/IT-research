# 🌐 NAT IP(Network Address Translation IP)

## 1. NAT IP란?

NAT(Network Address Translation)는  
사설 IP(Private IP)를 공인 IP(Public IP)로 변환해서 외부와 통신할 수 있도록 만드는 기술이다.

즉, 내부 서버들은 인터넷에 직접 노출되지 않고,
중간 장비(L4, 방화벽, NAT Gateway, 라우터 등)가 대신 외부와 통신한다.

이때 외부에 보여지는 공인 IP를 일반적으로 NAT IP라고 부른다.

---

# 2. 왜 NAT IP를 사용하는가?

외부 고객이 서비스를 사용하는 환경에서는
모든 서버를 인터넷에 직접 노출하지 않는다.

주요 목적은 다음과 같다.

| 목적 | 설명 |
|---|---|
| 보안 | 내부 서버 IP 숨김 |
| 공인 IP 절약 | 여러 서버가 하나의 공인 IP 사용 가능 |
| 네트워크 분리 | 내부망과 외부망 분리 |
| 방화벽 정책 단순화 | 특정 NAT IP만 허용 가능 |
| 트래픽 제어 | L4/L7 장비를 통해 제어 가능 |

---

# 3. 실제 서비스 환경 예시

```text
[고객 인터넷]
       ↓
service.company.com
       ↓
공인 NAT IP (52.10.10.10)
       ↓
L4 / 방화벽
       ↓
WEB 서버 (10.0.0.10)
       ↓
WAS 서버 (10.0.1.20)
       ↓
DB 서버
```

예시 IP:

| 구성 | IP |
|---|---|
| NAT 공인 IP | 52.10.10.10 |
| WEB 서버 | 10.0.0.10 |
| WAS 서버 | 10.0.1.20 |

외부 고객은 실제 내부 서버 IP인 `10.x.x.x` 를 절대 볼 수 없다.

고객 입장에서는:

```text
https://service.company.com
↓
52.10.10.10
```

으로만 보인다.

---

# 4. NAT 동작 원리

NAT는 크게 두 가지 흐름으로 동작한다.

- 외부 → 내부
- 내부 → 외부

---

# 5. 외부 고객 요청 시 NAT 동작 방식

예시 상황:

```text
고객 브라우저
↓
https://service.company.com
↓
52.10.10.10:443
```

고객은 도메인을 통해 접속하지만 실제 DNS 조회 결과는:

```text
service.company.com → 52.10.10.10
```

이다.

즉 고객 요청은 먼저 NAT 공인 IP로 들어온다.

---

## 실제 NAT 치환 과정

고객 요청:

```text
클라이언트
↓
52.10.10.10:443
```

NAT/L4 장비 내부에서는:

```text
52.10.10.10:443
↓
10.0.0.10:443
```

로 변경된다.

즉 NAT 장비가:

```text
공인 IP → 내부 사설 IP
```

로 목적지를 변환해주는 것이다.

이를 DNAT(Destination NAT)라고 부른다.

---

## 흐름 전체 예시

```text
고객
↓
52.10.10.10:443
↓
[NAT/L4]
↓
10.0.0.10:443
↓
WEB 서버 처리
```

WEB 서버는 실제로는 사설망 IP를 사용하고 있지만,
고객은 이를 알 수 없다.

---

# 6. 내부 서버가 외부 호출 시 NAT 동작

예시:

```text
WEB 서버 : 10.0.0.10
외부 API : 20.20.20.20
```

WEB 서버가 외부 API 호출:

```text
10.0.0.10 → 20.20.20.20
```

처럼 보이지만 실제 외부에서는:

```text
52.10.10.10 → 20.20.20.20
```

으로 보인다.

즉 NAT 장비가:

```text
사설 IP → 공인 NAT IP
```

로 출발지 IP를 변환한다.

이를 SNAT(Source NAT)라고 부른다.

---

# 7. 방화벽 허용 시 중요한 점

실무에서 가장 많이 헷갈리는 부분이다.

예시:

```text
WEB 서버 : 10.0.0.10
NAT IP : 52.10.10.10
외부 업체 서버 : 20.20.20.20
```

외부 업체 입장에서는:

```text
52.10.10.10
```

만 보인다.

따라서 방화벽 허용 요청 시:

❌ 잘못된 요청

```text
10.0.0.10 허용 요청
```

⭕ 올바른 요청

```text
52.10.10.10 허용 요청
```

즉 외부 업체는 내부 사설 IP를 절대 볼 수 없고,
오직 NAT 공인 IP만 인식한다.

---

# 8. NAT 종류

## 1) SNAT(Source NAT)

출발지 IP 변경

```text
10.0.0.10
↓
52.10.10.10
```

주로 내부 서버가 외부 API 호출 시 사용한다.

---

## 2) DNAT(Destination NAT)

목적지 IP 변경

```text
52.10.10.10
↓
10.0.0.10
```

외부 고객 서비스 유입 시 사용한다.

---

# 9. NAT IP 확인 방법

## Linux 서버에서 확인

외부에 실제 어떤 IP로 나가는지 확인:

```bash
curl ifconfig.me
```

또는:

```bash
curl https://api.ipify.org
```

출력 예시:

```text
52.10.10.10
```

이 값이 실제 NAT IP이다.

# 10. 클라우드 환경 NAT 예시

## AWS

주로 다음 조합을 사용한다.

- NAT Gateway
- Internet Gateway
- Elastic IP

구성 예시:

```text
Private Subnet 서버
↓
NAT Gateway
↓
Elastic IP
↓
인터넷
```

---

## Kubernetes 환경

Pod는 일반적으로 사설 IP를 가진다.

외부 통신 시:

```text
Pod IP
↓
Node NAT
↓
공인 NAT IP
```

형태로 나가게 된다.

---

# 11. NAT와 L4 차이

| 구분 | NAT | L4 |
|---|---|---|
| 역할 | IP 변환 | 트래픽 분산 |
| 주요 목적 | 내부망 보호 | 부하 분산 |
| 동작 계층 | Network Layer | Transport Layer |
| 대표 기능 | SNAT / DNAT | Load Balancing |
| 외부 노출 | NAT IP | Virtual IP(VIP) |

# 13. 핵심 정리

```text
- NAT는 사설 IP와 공인 IP를 변환하는 기술이다.
- 외부 고객은 내부 서버 IP를 직접 볼 수 없다.
- 외부에는 NAT 공인 IP만 보인다.
- 고객 요청은 NAT 장비에서 내부 서버 IP로 치환된다.
- 내부 서버가 외부 호출 시에는 NAT 공인 IP로 변경되어 나간다.
- 방화벽 허용 시 실제 서버 IP가 아니라 NAT IP를 허용해야 한다.
- DNAT는 외부 → 내부 변환이다.
- SNAT는 내부 → 외부 변환이다.
- L4는 트래픽 분산이고 NAT는 IP 변환이라는 차이가 있다.
```
