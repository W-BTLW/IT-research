## 비대면 이체 환경에서의 망(Network) 차이

### 당행계좌 -> 당행계좌 (내부 트랜잭션)
외부기관과의 연동없이 은행 내부 시스템 안에서 모든 처리가 완결됨
- 사용망 : **내부 계정계망**
- 주요 프로세스 :
   1. 채널서버 : 사용자의 이체요청 수신
   2. 계정계 : 출금 계좌와 입금 계좌가 모두 당행 소속임을 확인
   3. DB 트랜잭션
       - STEP 1 : A 계좌 잔액 차감 (Update)
       - STEP 2 : B 계좌 잔액 가산 (Update)
       - STEP 3 : 이체 결과 원장 반영 및 이력 저장
   4. 응답 : 외부망 통신이 없으므로 지연이 거의 없이 즉시 완료
 

### 당행계좌 -> 타행계좌 (금융공동망 이체)
금융결제원(KFTC)의 중계망을 통해 타 은행 시스멭과 "직접"통신
- 사용망 : **전자금융공동망(FEP를 통한 금결원 연동망)**
- 주요 프로세스 :
    1. 채널서버 : 타행 이체 요청 수신
    2. 계정계 : 출금 처리 후 대외계(FEP)로 이체 전문 전달
    3. 대외계(FEP) : 금융결제원 표준 규격 전문(ISO8583 등)으로 변환하여 금융결제원에 송신
    4. 금융결제원 : 수신 은행(타행)으로 전문 중계
    5. 타행 : 입금 처리 후 응답 전문을 금결원에 반환 -> 금결원이 다시 당행 대외계로 전달
    6. 결과확정 : 당행 계정계에서 타행 응답(성공/실패)을 확인하여 최종처리
 
### 타행계좌 -> 당/타행계좌 (오픈뱅킹망 이체)
다른 은행에 있는 내 돈을 가져오거나 보낼 때 사용하며, API 활용
- 사용망 : **오픈뱅킹 공동망 (REST API 기반 인프라)**
- 주요 프로세스 (우리은행앱에서 A은행계좌의 돈을 출금하여 C은행계좌로 보낼때)
    1. 채널서버 : 오픈뱅킹 이체 요청 수신
    2. 계정계 : 대외계모듈(또는 오픈뱅킹 전용 API 게이트웨이)로 데이터 송신, 이 때 계정계 내부데이터가 금결원 오픈뱅킹 표준API규격(JSON)으로 변환
    3. 출금이체(API 호출1)
       - 통신 : 우리은행서버 -> 금결원 오픈뱅킹 플랫폼 (출금이체 API호출)
       - 내용 : A은행에 있는 사용자 계좌에서 우리은행에게 줄 돈 XX원을 출금해달라
       - 결과 : 금결원이 A은행에 요청하여 돈을 뺀 뒤, 성공응답을 보내옴. 이 때 자금은 금결원 정산 계좌에 예치된 상태
    4. 입금이체(API 호출20
       - 통신 : 우리은행서버 -> 금결원 오픈뱅킹 플랫폼 (입금이체 API호출)
       - 내용 : 방금 금결원에서 들어온 돈을 C은행 사용자 계좌로 넣어달라
       - 결과 : C은행 계좌에 돈이 입금되고 최종 성고 응답 내려옴
    5. 계정계 원장 반영 및 앱 응답
 
### 공동망 VS 오픈뱅킹망 주요 차이점
1. 인프라의 위치
    - 금융공동망 : 은행의 대외계(FEP)와 직접 연결됨. 전용선을 사용하여 보안수준이 매우 높고 은행간의 '직접연결'에 가까움
    - 오픈뱅킹망 : 금결원이 구축한 오픈플랫폼(API G/W)를 한 번 더 거침. 핀테크 업체들도 참여할 수 있도록 문턱을 낮춘 '중계 플랫폼' 성격이 강함
2. 권한의 차이
    - 금융공동망 : 계좌 주인(은행)이 직접 명령을 내리는 구조 -> 책임이 은행에 있음 그래서 인증보안 아직도 받는거..
    - 오픈뱅킹망 : 제3자(핀테크 앱 등)가 고객의 권한을 위임 받아 명령을 내리는 구조 -> 고객의권한 위임받았기에 책임을 고객과 양분함! 자동납부 걸려있음 마치 자동이체 뺴가듯이 인증보안 최대한 SKIP하고 빠르게 이체하기 위해서
