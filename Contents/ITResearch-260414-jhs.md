# 1) 안드로이드 LMK 발동 조건

## 개요
- Android는 메모리 부족 상황에서 **Low Memory Killer Daemon(lmkd)**를 통해 프로세스를 종료
- OOM(Out Of Memory) 발생 전에 선제적으로 메모리를 확보하는 메커니즘

---

## 발동 조건 (핵심)

### 1. 메모리 부족 상태 진입
- free memory + file cache가 임계치 이하로 감소
- 또는 메모리 압박(PSI, Pressure Stall Information) 증가

👉 단순 “남은 메모리”뿐 아니라 **실제 시스템 지연(stall)**도 기준

---

### 2. kill 대상 프로세스 존재
- 프로세스는 우선순위(OOM score_adj)에 따라 정렬됨

우선순위 (높음 → 낮음):
1. Foreground (현재 사용 앱)
2. Visible
    - 화면에 일부 보이거나 사용자에게 영향 있는 상태
    - 완전히 foreground는 아니지만 “사용 중”으로 간주
3. Service (백그라운드)
4. Cached (현재 아무일도 안하지만 빠른 재실행을 위해 메모리에 남아있는 상태)

👉 LMK는 **낮은 우선순위부터 순차적으로 종료**

---

## 실제 트리거 방식

### (1) minfree 기반 (전통 / 정적임)
- 메모리 구간별 threshold 존재
- 구간마다 kill 대상 정의

대략적인 비율:
- 10~15% 이하 → cached kill 시작
- 5~10% → service kill
- 5% 이하 → aggressive kill

---

### (2) PSI 기반 (현대 Android 핵심 / 동적임)
- CPU / Memory stall 시간 기반 판단

👉 특징:
- 메모리 여유 있어도 kill 가능

---

## 한 줄 정리
> “메모리 부족 또는 압박 발생 시, 우선순위 낮은 프로세스를 선제적으로 종료”

---

# 2) iOS와의 정책 비교

## 기본 철학

### Android
- 다양한 기기 환경 (RAM 편차 큼)
- 멀티태스킹 자유도 높음
- 성능 유지 중심

👉 특징:
- 자주, 선제적으로 kill

---

### iOS
- HW + SW 통합 관리
- 앱 lifecycle 엄격
- 백그라운드 제한 강함

👉 특징:
- 최대한 유지 후, 한 번에 정리 (Jetsam)

---

## 동작 방식 비교

| 구분 | Android | iOS |
|------|--------|-----|
| 메모리 관리 | lmkd | Jetsam |
| kill 타이밍 | 자주, 선제적 | 늦게, 일괄적 |
| 백그라운드 | 생존 보장 없음 | suspended 상태 유지 |
| 앱 전환 | 초기화 자주 발생 | 상태 유지 잘됨 |

---

## 체감 차이

- Android: 앱 전환 시 초기화 자주 발생
- iOS: 앱 유지되다가 특정 순간 한 번에 종료

---

## 한 줄 정리
> Android는 “성능 유지”, iOS는 “UX 유지” 중심의 메모리 정책

# 3) 금융앱에서 LMK 발생 가능성이 높은 이유

## 1. 높은 메모리 사용량

### 보안 모듈
- 키보드 보안, 루팅 탐지, 위변조 방지
- native 라이브러리 → 메모리 상주

---

### WebView 기반 인증
- 인증/결제 프로세스
- JS + DOM + 렌더링 메모리

👉 “앱이 아니라 브라우저 수준 메모리 사용”

---

### 리소스 사용량
- 고해상도 UI
- 차트, PDF, 인증서 처리

---

## 2. 백그라운드 취약 구조

- 보안 정책상 background 서비스 제한
- foreground service 사용 어려움

👉 결과:
- background 진입 시 즉시 kill 후보

---

## 3. 상태 복원 어려움

- 보안 이유로 메모리 상태 유지 최소화
- 토큰/세션을 디스크에 적극 저장하지 않음

👉 결과:
- kill 시 복구 불가 → 로그인부터 다시

---

## 4. PSI 기반 kill에 취약

- 순간 메모리 스파이크
- GC 지연
- native 메모리 증가

👉 조건 만족 시 즉시 종료

---

## 한 줄 정리
> 금융앱은 “메모리 사용량 높고 + 백그라운드 보호 없고 + 상태 복원 어려운 구조”라서 LMK에 취약하다
