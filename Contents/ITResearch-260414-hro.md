# AIOps

### AIOps란?
IT인프라가 마이크로서비스 아키텍처(MSA)와 클라우드 네이티브 환경으로 복잡해짐에 따라, 사람이 일일이 로그를 분석하고 장애를 대응하는 시대는 끝났다.

AIOps(IT운영을 위한 인공지능)는 빅데이터, 머신러닝, AI 기술을 활용해 IT시스템의 이상 징후를 탐지하고, 이벤트를 상관분석하며, 근본 원인을 파악해 운영을 자동화하는 플랫폼.

인프라 복잡성을 줄이고 예방적 조치를 통해 장애 해결 시간을 단축하며 운영 효율성을 극대화한다.

<br>

### AIOps의 정의와 등장 배경
AIOps는 단어 그대로 IT운영(Ops)에 인공지능(AI) 기술을 결합한 개념이다. 

가트너(Gartner)가 처음 제시한 이 용어는 머신러닝과 빅데이터 분석을 통해 IT인프라에서 발생하는 방대한 데이터를 실시간으로 처리하고 지능적으로 의사결정을 내리는 기술을 의미한다.


그럼 왜 AIOps가 필요한가?
1. 데이터의 폭증 : 수천 개의 컨테이너와 서비스에서 쏟아지는 로그, 메트릭, 트레이싱 데이터를 사람이 분석하는 것은 불가능에 가깝다.
2. 복잡한 인과관계 : 장애가 발생했을 때 원인이 네트워크인지, 코드인지, 혹은 특정 클라우드 설정인지 파악하는 데 너무 많은 시간이 소요된다.
3. 전조 현상 파악의 한계 : 기존의 임계치 기반 모니터링은 사고가 터진 후에야 알람을 울릴 뿐, 장애를 예측하지 못한다.

<br>

### AIOps의 핵심 작동 원리
AIOps는 단순히 하나의 도구가 아니라, 데이터를 수집하고 가공하여 지능을 부여하는 일련의 과정이다.
1. 데이터 수집 및 통합 : 다양한 소스(로그, API, 이벤트)로 부터 파편화된 운영 데이터를 한곳으로 모은다
2. 패턴 탐지 및 정규화 : 수집된 데이터에서 노이즈를 제거하고, 평소와 다른 '이상징후'를 머신러닝 알고리즘으로 찾아낸다
3. 인과 분석 : 여러 곳에서 동시다발적으로 발생하는 알람들 사이의 연관성을 분석한다. 수백 개의 알람 중 '근본 원인'이 무엇인지 식별하는 과정이다
4. 의사결정 및 자동화 : 분석된 결과를 바탕으로 운영자에게 해결책을 권고하거나, 사전에 정의된 스크립트를 통해 시스템이 스스로 복구하도록 명령한다.

<br>

### AIOps의 주요 활용 사례
실무에서 AIOps는 다음과 같은 영역에서 혁신을 일으킨다.
1. 지능형 경보 알람 : 불필요한 중복 알람을 차단하고, 정말 중요한 장애 상황만 핵심 요약하여 전달한다
2. 장애 예측 및 사전 대응 : 과거 데이터를 학습하여 특정 패턴이 나타날 때 "30분 내로 메모리 부족 장애가 발생할 확률 90%"와 같은 예측 정보를 제공한다.
3. 근본 원인 분석 : 장애 발생 시 수천 개의 로그를 뒤지는 대신, AI가 장애의 시작점과 확산 경로를 시각화하여 보여준다
4. 용량 최적화 : 트래픽 패턴을 분석하여 서버 자원을 자동으로 늘리거나 줄여 비용을 최적화한다.

<br>

### 성공적인 도입을 위한 고려사항
AIOps는 만능 해결사가 아니며, 도입 전 반드시 확인해야 할 요소들이 존재한다.
1. 데이터의 품질 : "Garbage In, Garbage Out"원칙이 적용된다. 깨끗하고 정제된 데이터가 충분히 확보되어야 AI가 정확한 판단을 내릴 수 있다.
2. 단계별 접근 : 처음부터 모든 것을 자동화하기보다, 알람 통합 -> 이상 탐지 -> 근본 원인 분석 -> 자동 대응 순으로 범위를 넓혀가는 것이 현실적이다.
3. 사람과의 협업 : AI의 판단을 최종적으로 검증하고 시스템에 반영하는 것은 여전히 운영자의 몫이다. AI를 '대체재'가 아닌 '강력한 보조 도구'로 인식해야 한다.

<br>

### Kafka + ELK 조합
Kafka와 ELK Stack의 조합은 AIOps를 구현하기 위한 표준적인 인프라지만, 자동으로 AIOps가 되는 것은 아니다
Kafka와 ELK는 '고성능 컨베이어 벨트와 창고'를 만든 것이고, 여기에 똑똑한 AI 분석가를 앉혀야 비로소 AIOps가 완성된다.

<br>

엘라스틱은 단순히 데이터를 쌓는 DB를 넘어, Search AI라는 브랜드로 운영 지능화를 이미 실현하고 있음.

<br>

AIOps로 인정받기 위한 3가지 추가 조건
1. 이상 탐지 : 사람이 "CPU 90%면 알람 줘" 라고 정하는게 아니라, AI가 "평소 월요일 오전보다 트래픽이 이상하게 높네?"라고 스스로 판단해야 한다.
2. 연관 분석 : DB장애와 WAS 장애 알림이 동시에 떴을 때, AI가 "이건 WAS문제가 아니라 DB가 원인이야"라고 집어내야 한다.
3. 예측 : "이 추세라면 1시간 뒤에 메모리가 꽉 차서 서버가 뻗을 것이다"라고 미리 알려줘야 한다.



<br>

### 결론
결국 AIOps의 본질은 운영자의 고단한 수작업을 줄이고, 서비스의 가용성을 극대화하는데 있다.
인프라가 고도화될수록 데이터 속에서 의미 있는 통찰을 뽑아내는 능력은 곧 개발팀의 경쟁력이 될 것이다.
