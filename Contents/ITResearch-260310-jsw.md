# 멀티 프로세스(Multi Process)와 멀티 스레드(Multi Thread)

현대 운영체제와 서버 프로그램은 **여러 작업을 동시에 처리**하기 위해 다양한 실행 모델을 사용한다. 그 대표적인 방식이 **멀티 프로세스**와 **멀티 스레드**이다. 두 개념은 모두 *동시성(Concurrency)* 또는 *병렬성(Parallelism)을* 구현하기 위한 방법이지만, **자원 구조와 실행 방식에서 큰 차이**가 있다.

---

## 1. 프로세스(Process)란?

프로세스는 **운영체제가 실행 중인 프로그램을 관리하기 위한 독립적인 단위**이다.

프로세스는 다음과 같은 자원을 독립적으로 가진다.

- 메모리 공간 (Heap, Stack, Code, Data)
- 파일 디스크립터
- CPU 스케줄링 정보
- OS에서 할당한 각종 시스템 자원

즉, **프로세스는 서로 완전히 분리된 실행 환경**을 가진다.

예시

- 웹 브라우저
- 데이터베이스 서버
- 자바 애플리케이션

각 프로그램은 보통 **하나 이상의 프로세스**로 실행된다.

---

# 2. 멀티 프로세스 (Multi Process)

멀티 프로세스는 **여러 개의 프로세스를 동시에 실행하여 작업을 처리하는 방식**이다.

예시

```

프로세스 A
프로세스 B
프로세스 C

```

각 프로세스는 **독립적인 메모리 공간**을 사용한다.

### 특징

**장점**

- 프로세스 간 **메모리 충돌이 발생하지 않음**
- 하나의 프로세스가 죽어도 **다른 프로세스에는 영향이 적음**
- 안정성이 높음

**단점**

- 프로세스 생성 비용이 큼
- **컨텍스트 스위칭 비용이 큼**
- 프로세스 간 통신(IPC)이 복잡

### 프로세스 간 통신(IPC)

프로세스는 메모리를 공유하지 않기 때문에 통신이 필요하다.

대표적인 방법

- Pipe
- Socket
- Shared Memory
- Message Queue

---

# 3. 스레드(Thread)란?

스레드는 **프로세스 내부에서 실행되는 작업 단위**이다.

하나의 프로세스는 **여러 개의 스레드**를 가질 수 있다.

예시

```

프로세스
├─ 스레드 1
├─ 스레드 2
└─ 스레드 3

```

스레드는 **같은 프로세스의 자원을 공유**한다.

공유되는 것

- Heap 메모리
- 전역 변수
- 파일 디스크립터

하지만 **각 스레드는 자신의 Stack을 가진다.**

---

# 4. 멀티 스레드 (Multi Thread)

멀티 스레드는 **하나의 프로세스 내부에서 여러 스레드를 동시에 실행하는 방식**이다.

예시

```

웹 서버 프로세스
├─ 요청 처리 스레드
├─ 로그 처리 스레드
└─ 캐시 관리 스레드

```

### 특징

**장점**

- 생성 비용이 작다
- 컨텍스트 스위칭이 빠르다
- 메모리 공유로 데이터 교환이 빠르다

**단점**

- 메모리를 공유하기 때문에 **동기화 문제가 발생**
- 잘못 설계하면 **Race Condition** 발생
- 한 스레드의 오류가 **전체 프로세스에 영향을 줄 수 있음**

---

# 5. 멀티 프로세스 vs 멀티 스레드

| 구분 | 멀티 프로세스 | 멀티 스레드 |
|---|---|---|
| 메모리 | 서로 독립 | 대부분 공유 |
| 안정성 | 높음 | 상대적으로 낮음 |
| 생성 비용 | 큼 | 작음 |
| 통신 | IPC 필요 | 메모리 공유 |
| 컨텍스트 스위칭 | 무거움 | 가벼움 |

---

# 6. 실제 시스템에서의 사용 예

### 멀티 프로세스 기반

- Nginx Worker Process
- Node.js Cluster
- 데이터베이스 서버

특징

```

Master Process
├─ Worker Process
├─ Worker Process
└─ Worker Process

```

각 프로세스가 독립적으로 요청을 처리한다.

---

### 멀티 스레드 기반

- Java Web Server
- Tomcat
- Spring 서버

예시

```

Server Process
├─ Request Thread 1
├─ Request Thread 2
├─ Request Thread 3

```

요청마다 새로운 스레드를 생성하거나 Thread Pool을 사용한다.

---

# 7. 언제 무엇을 선택할까?

일반적으로 다음과 같은 기준을 사용한다.

**멀티 프로세스가 유리한 경우**

- 높은 안정성이 필요할 때
- 프로세스 간 격리가 중요한 경우
- 서로 다른 프로그램 실행

**멀티 스레드가 유리한 경우**

- 빠른 데이터 공유가 필요할 때
- 많은 요청을 빠르게 처리해야 할 때
- 하나의 프로그램 내부 병렬 처리

---

# 8. 정리

멀티 프로세스와 멀티 스레드는 모두 **동시에 여러 작업을 수행하기 위한 구조**지만 접근 방식이 다르다.

**멀티 프로세스**

> 안정성 중심 구조

**멀티 스레드**

> 성능 중심 구조

현대 서버 시스템은 실제로 **두 가지 방식을 혼합해서 사용**하는 경우가 많다.

예시

```

멀티 프로세스
↓
각 프로세스 내부 멀티 스레드

```

이러한 구조는 **성능과 안정성을 동시에 확보**하기 위한 설계이다.
