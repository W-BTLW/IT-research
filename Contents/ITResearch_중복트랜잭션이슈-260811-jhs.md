# OkHttp 자동 재시도 & 중복 트랜잭션 ID 이슈 정리

## 1. OkHttp 자동 재시도로 인한 중복 TxID 에러
OkHttp는 기본적으로 네트워크 오류 발생 시 자동 재시도(`retryOnConnectionFailure=true`)를 진행.

* **발생 원인**: 서버가 요청을 정상 처리했으나, 네트워크 문제로 **응답 패킷만 클라이언트에 전달되지 못한 경우** 발생.
* **이슈 발생**: OkHttp가 동일한 `TxID`로 자동 재시도 → 서버는 이미 처리된 `TxID`이므로 **"중복 트랜잭션 ID"** 에러 반환.

---

## 2. 자동 재시도를 무작정 끄면 안 되는 이유
자동 재시도를 완전히 끄면 순간적인 네트워크 튀김(LTE/5G ↔ Wi-Fi 전환, 소켓 타임아웃 등)에 앱이 취약해짐.

* **iOS 사례 (재시도 미처리 시 발생하는 네트워크 에러 예시)**:
  * `NSURLErrorTimedOut` (`-1001`): 요청 시간 초과
  * `NSURLErrorCannotConnectToHost` (`-1004`): 서버 연결 실패
  * `NSURLErrorNetworkConnectionLost` (`-1005`): 데이터 전송 중 연결 끊김
  * **UX 문제**: 이러한 에러 발생 시 앱 단에서 재시도/예외 처리가 없으면 화면이 멈추는 **백화 현상**이나 불필요한 요청 실패 발생.
    -> IOS백화 문의 들어오면 프론트 인터맥스에는 네트워크 관련 오류가 찍혀있는데, 통합로그조회 서버 로그에는 아무것도 찍혀있지 않음
* **결론**: 조회(GET) 등 멱등성이 보장되는 요청에서는 자동 재시도가 필수.

---

## 3. 해결 방안

### 3-1. Android (OkHttp)
* **서버 멱등성(Idempotency) 보장**
  * 서버가 동일한 `TxID` 요청을 여러 번 받아도 에러를 던지지 않고, **기존 성공 응답(200 OK)을 동일하게 재반환**하도록 서버-클라이언트 스펙을 표준화.
  * 단, 특정 API에서만?

### 3-2. iOS
* **앱 단 자동 재시도 구현**: Alamofire `RequestInterceptor` 등을 활용해 `-1001`, `-1005` 등 단순 네트워크 오류 발생 시 1~2회 자동 재시도.
* **명확한 UX 제어**: 최종 실패 시 백화 현상 방지를 위해 Alert 팝업 노출 및 재시도 버튼 제공.
